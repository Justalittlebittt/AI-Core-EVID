# V3.2 — Bounded CNINFO announcement-directory UI check (2026-11-20)

## Purpose
Assess whether initial share-repurchase announcements can be assembled as a **complete, decision-time cohort**, including non-announcing controls, without coding an indiscriminate crawler. This is **not a predictive experiment**.

## Observed live browser test (read-only)
- Website: https://www.cninfo.com.cn/new/commonUrl?url=disclosure/list/notice
- Read-only browser run: https://agent.tinyfish.ai/runs/2532c42f-de7d-4835-9fdd-2936e105f403
- Site form was set to **2026-11-18 through 2026-11-18**, with **Shanghai and Shenzhen** selected.
- Browser agent reported page UI count **1,223 announcements**, 30 per page => **41 calculated pages**. The count is an observed UI response, **not independently reconciled against a second provider or complete export**.
- First displayed example in agent's report: `300712` 永福股份, 担保额度进展公告, **2026-11-18 07:20**.
- One displayed repurchase-related item: `300390`, 回购股份事项前十名股东及前十名无限售条件股东持股情况的公告, **2026-11-18 04:32**. **This is not an initial new-plan event**; title matching for “回购” alone would contaminate treatment labels.
- **Critical correction:** the browser report *calls page 4 the final page 41* while describing navigation that only reached page 4. Its claimed final-page identifiers are **not verified**. No claim is made that page 41 is reachable or all 1,223 entries enumerated.
- Displayed six-digit stock codes are **security identities, not unique announcement document IDs**. A complete ledger would need an actual announcement/document ID or stable source PDF link per row.
- The displayed minutes may be UI timestamps but require confirmation of semantics, time zone, first publication versus update, and whether such timestamps are historically stable.

## Primary/secondary cross-check and risks
- SSE has a separate stock list and announcement listing: https://www.sse.com.cn/assortment/stock/ and https://www.sse.com.cn/disclosure/listedinfo/announcement/ . A current stock list is not automatically a historically point-in-time eligible universe.
- CNINFO publicly describes itself as an official SZSE information-disclosure website, but a browseable UI does not establish an official supported batch API, published completeness SLA or authorized bulk redistribution.
- Independent code examples describe `POST https://www.cninfo.com.cn/new/hisAnnouncement/query` with pagination; this is **community-reported** and was **not live POST-tested in this batch**. Some third parties report hard page-depth limits and parameter regressions, so the 41-page UI count cannot be treated as proof all pages are machine-readable. Illustrative references:
  - https://github.com/Hsiangpo/cninfo-/blob/main/src/cninfo_ssgs/cninfo_api.py
  - https://www.sagax.cn/data/v1/tables/info_announcement.html
  - https://davinci37.github.io/Introduction-to-Quantitative-Investment/%E7%AC%AC13%E7%AB%A0%20%E6%95%B0%E6%8D%AE%E8%B5%84%E6%BA%90%20%E7%AC%AC4%E8%8A%82%20%E5%B7%A8%E6%BD%AE%E8%B5%84%E8%AE%AF.html

## Follow-up live browser attempt (2026-11-20) — inconclusive, do not combine counts

- Run evidence: https://agent.tinyfish.ai/runs/36b0c518-7de7-4e6c-990e-27bfad72fefc
- Attempted exactly the same 2026-11-18 through 2026-11-18 Shanghai+Shenzhen date-scoped final-page check. The **end date selector was not successfully set**, so the apparent `3,129` rows, page 1, around 20 visible items per page and UI offering up to 100 pages are from **a different or unverified effective filter**. They cannot contradict or validate the prior 1,223 / 41-page reported slice, and cannot be used as a cohort.
- Did not reach page 41, verify last-page row count, or inspect end-of-result rows. **No full pagination success is claimed.**
- Agent observed a CNINFO detail URL structure of `/new/disclosure/detail?stockCode=601899&announcementId=1225680342&orgId=9900004143&announcementTime=2026-11-19`. Thus an `announcementId` **field format exists** and differs from six-digit `stockCode`, but the identity, permanence and timestamp semantics of that *example* are not independently verified against a PDF in this attempt. Treat as a URL-format observation only.
- The two browser attempts used UI navigation and provided nonidentical reported page sizes; they **do not establish stable filtering, full enumeration, historical completeness, or unbiased event/non-event coverage**.
- **Operational decision:** do not run another long identical calendar-click attempt or ask the user to manually finish. Avoid repeated UI work; for source admission use a bounded, independently reproducible request/response test (where lawful/available) that records actual date, board filters, result total, page size, distinct document IDs and last-page count. Without that proof, mark `SOURCE_NOT_ADMITTED` and do not train/backtest.
- Scientific status unchanged: `NO VERIFIED ALPHA / NO BUY`. No frozen experimental rules or outcomes accessed.

## Third and final transport check — 2026-11-20

**Purpose:** Test the previously suggested reproducible JSON POST route once, without reopening historical returns.

1. Public implementation references (descriptions, **not** independently verified exchange support):
   - https://github.com/Hsiangpo/cninfo-/blob/main/src/cninfo_ssgs/cninfo_api.py specifies `POST /new/hisAnnouncement/query`, date syntax `2026-11-18~2026-11-18`, `pageNum`, `pageSize`, `column`, and `announcements`.
   - https://github.com/itisaevalex/ChinaCninfoScraper reports possible silent approximately 100-page truncation; this is a third-party claim and not a measured current backend cap.
2. **Actual local POST:** HTTPS DNS resolution for `www.cninfo.com.cn` failed in the active execution container (`requests.exceptions.ConnectionError` / `NameResolutionError`), so there was **no HTTP status, JSON, count, document ID, or endpoint success**.
3. **Actual live browser alternative:** https://agent.tinyfish.ai/runs/0d4fdf34-9918-41c0-917f-97e01e43ab49 . The browser tool could navigate and extract the public UI but **could not execute page JavaScript/fetch or capture JSON requests**. Its unqualified page view reported `922` items, `30` per page, and `16` pages: 922/30 requires at least **31** pages, so these returned summary numbers are internally inconsistent. The two dated browser attempts also failed to prove the intended full slice; **none of the 1,223 / 3,129 / 922 counts is a verified complete cohort**.
4. **Gate verdict for this execution environment:** `SOURCE_NOT_ADMITTED (TRANSPORT_AND_COMPLETENESS_UNVERIFIED)`. This is **not** a scientific finding of zero buyback alpha or a permanent statement that CNINFO cannot be accessed elsewhere. Stop this acquisition branch for now: no more calendar UI loops, no new scraper/CI, no headline-only backtest.
5. **Problem elimination and P0 redirect:** Instead of another tool-specific retrieval workflow, use existing real-issuer sourced research and already working free-data flows for a decision-time **NO ACTION** output, while seeking a separate independently testable full-universe 20-session mechanism. Avoid using the previously failed SSE margin incremental experiment as a fresh factor merely because its source is available. No frozen cohort, sealed results or trade authorization changed.

**Validation:** Exact target POST attempt and alternate browser execution were attempted; failure modes and contradictory pagination arithmetic recorded. No response-level or production integration tests passed, and no alpha test was run.
